## Immutable fixture and A → B → A design for a later task

1. **A provenance.** Freeze a Manager-approved accepted-current canonical product SHA at execution time; extract only the immutable runtime allowlist from its Git tree into a new temporary directory outside the repository and user's browser profile. At minimum the WR-146 29 checked assets plus directly referenced logo and other same-origin resources discovered from HTML, scripts and worker `CORE_ASSETS`; reject any missing file. Compute per-path Git blob ID and SHA-256 and the sorted `path SHA256hex\n` manifest. Verify extracted A bytes exactly equal that tree before starting. Use the **frozen repository tree**, not an assumption that a live Pages fetch equals A. Record original A manifest, command-bar and worker hashes, A cache name and HTML hash. No cookies, credentials, real saved drafts or extension install; static shipped 2026 datasets are inert fixture bytes, not refreshed/live source intake.
2. **B construction.** Copy A fixture to a second immutable fixture manifest. Change only copied `index.html` to add an unambiguous visible `NONPRODUCTION RECOVERY FIXTURE B` badge, and copied `service-worker.js` to use a distinct fixture-only cache name (same original prefix, unique B suffix). Avoid altering app logic, rankings, datasets, recommendation text, API endpoints or production files. Log exact patch and SHA-256/Git-style blob of both changed files; assert all other copied files equal A and the badge is absent from A. The two changes are benign, intentional, visually and byte-discriminable and exercise worker update. Never publish B on a public host.
3. **Transition.** Serve A over one loopback origin and stable port; snapshot receipt. Atomically swap the fixture document root from immutable A directory to immutable B directory without changing the origin. Record the swap timestamp and A/B manifests; the server must not serve a mixed tree during the switch. Exercise fresh and existing browser contexts online and offline, with explicit worker update checks and reload. Restore by atomically switching back to the **same immutable A directory**, not re-creating it from memory; assert exact A manifest and loaded A behavior. Retain evidence and repeat stability observations before teardown. A and B fixture directories stay immutable; only a documented server-root pointer changes.
4. **Network/storage boundary.** Bind exclusively to `127.0.0.1` on an ephemeral held port; restrict browser requests to that exact origin and fail on any unexpected request. Service-worker requests can evade ordinary Playwright page routing, so a future executor must additionally enforce loopback-only egress at the process/container/network boundary or prove an equivalent deny rule and capture all attempted external traffic. No localhost forwarding, public tunnel, ESPN mock/provider request, real ESPN account, extension session, user profile or shared `localStorage`. Use isolated contexts/profile, test-only draft state and clean fixture directories. If egress isolation cannot be demonstrated, **stop before loading the app**.

**Future authorization/resource inventory:** Manager must separately authorize temporary filesystem fixture and harness writes/execution, local loopback port/browser process and cleanup; authorize any repository test-script change only through a separately scoped Builder task and applicable review/CI. Chromium installation/download or reuse of an existing CI runner needs separate execution authority and resource/network budget; current scratch package has Playwright but no executable Chromium. No new account, external repository/site/environment, Pages setting, token or secret is proposed. A loopback fixture with bundled static data does not require credentials or provider access. Preserve the existing War Room product/full CI separately; this fixture experiment does not substitute for guarded production merge/full CI. Run only for a bounded recorded observation period, with explicit convergence checks rather than a fixed ten-minute wait.

Diagnostic cache-busting query/explicit `Cache-Control: no-cache` requests help inspect network bytes, but ordinary requests and browser loaded resources are independently required. Worker offline `caches.match(..., {ignoreSearch:true})` can return old bytes despite a query. Inspect controller script hash, registration state, cache keys/entries, and response source; force update/reload only as a **separately logged remediation observation**, not silent evidence of normal convergence. No public `max-age=600` assertion follows from local response headers.

**Abort and cleanup:** stop on source SHA/tree drift, incomplete/copied fixture or mixed directory, unexpected external network attempt, failure to enforce loopback-only egress, browser/SW script error, A/B hash discrepancy, missing controller/update proof, B badge appearing at A, stale B after declared restoration, service-worker cache ambiguity, failure of no-provider smoke, or inability to remove local test resources. Freeze logs and manifests at failure; restore server pointer to original A only if safe, stop browser/server, delete isolated profile/fixture under separately authorized task, and record unresolved evidence. Never touch public Pages/main to “recover” a local failure.
