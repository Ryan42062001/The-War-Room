# WR-013 — Current Layout Efficiency & Usability Baseline Audit

TASK ID: WR-013
ROLE: Independent Auditor / QA
STATUS: ASSIGNED
PARALLEL WAVE: PW-001

## Objective
Independently measure the current War Room's draft-day layout efficiency, usability, responsive behavior, and interaction friction across desktop, tablet, and mobile so the Manager can distinguish evidence-backed layout problems from subjective design preference.

This is an audit/discovery task, not an implementation audit. Production changes are NOT authorized.

## Why it is needed
The user asked whether the website layout can be made more efficient. R&D WR-012 will research external patterns and propose improvements. WR-013 provides a separate current-product evidence stream so Manager synthesis is grounded in how the actual War Room behaves today.

## Independence rule
Perform the first-pass audit without reading WR-012's eventual recommendation artifact. The Auditor may read the Manager task specs and canonical state, but should avoid being anchored by R&D's conclusions until its own baseline findings are written.

## Audit questions
1. How much usable viewport is consumed by persistent chrome before the user reaches actionable board content?
2. Can a user determine `where am I in the draft`, `what should I do`, and `what is disappearing soon` quickly at each target viewport?
3. Are the primary draft controls visually dominant over low-frequency maintenance/settings/destructive controls?
4. Are search/filter/marking/board-view controls easy to find and operate under time pressure?
5. Are status and sync indicators informative without creating unnecessary visual competition?
6. Is Position Tiers efficient on desktop, tablet, and mobile, or does its composition degrade at specific widths?
7. Does the Overall view remain practically usable on small screens?
8. Is My Draft / roster information reachable with acceptable interaction cost and without losing board context unnecessarily?
9. Are there small or crowded interactive targets that are technically overflow-safe but ergonomically weak?
10. Are there duplicated controls, redundant labels, excessive vertical gaps, or unnecessary sticky layers?

## Required measurements / evidence
Record where possible:
- document horizontal overflow
- intentional internal horizontal scrollers
- sticky chrome total height and percentage of viewport height
- first vertical coordinate at which primary player-board content becomes visible
- number of primary player choices visible above fold
- touch/click target dimensions for frequently used controls
- interaction count for the core flows
- scroll distance required to move between recommendation, roster needs, and player board
- clipping/wrapping/crowding at breakpoint transitions
- browser console/page errors during audited flows

## Severity model
Use:
- CRITICAL — blocks or corrupts draft-day use
- HIGH — materially slows or risks wrong action under time pressure
- MEDIUM — recurring efficiency/accessibility friction with a practical workaround
- LOW — polish/density issue with limited draft-day impact
- OBSERVATION — measurable fact without a defect conclusion

This discovery audit does not need to issue a global production PASS/FAIL unless a genuine defect is found. The required result is an evidence-backed baseline and prioritized findings.
