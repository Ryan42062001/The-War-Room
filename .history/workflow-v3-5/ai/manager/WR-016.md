# WR-016 — Draft-Day Layout Efficiency Implementation

TASK ID: WR-016
ROLE: Implementation Engineer
STATUS: ASSIGNED
PARALLEL WAVE: PW-002

## Objective
Implement the bounded layout-efficiency improvements approved by Manager in WR-015 so the War Room preserves its current decision-focused architecture while reducing persistent chrome cost, low-frequency control competition, setup clutter, and touch/focus friction across desktop, tablet, and mobile.

This is a production UI task. It is **not** a redesign and must not alter ranking, scoring, recommendation, draft-state, persistence, or ESPN-sync semantics.

## Why it is needed
PW-001 produced two independent evidence streams:
- WR-012 R&D found that the strongest improvement is a coordinated persistent decision surface, progressive disclosure of maintenance/destructive actions, and collapsing Draft Setup after initialization/progress.
- WR-013 Auditor independently found MEDIUM concerns around persistent desktop/tablet vertical budget, low-frequency/destructive control competition, sub-30px frequent targets, and the 769–900px responsive band.

Manager WR-015 accepted the overlap and approved a bounded production milestone while rejecting a broad redesign.

Capture the pre-change values in test output or a role-owned implementation artifact so post-change claims are evidence-backed.

### 2. Coordinate the persistent decision hierarchy
The live draft decision loop must receive persistent priority over branding/setup/maintenance chrome.

Required outcome:
- remove or replace fragile independent fixed sticky offsets where wrapping can invalidate the geometry
- avoid stacking header/toolbar/status/navigation/command surfaces in a way that unnecessarily consumes the viewport
- preserve easy access to high-frequency draft controls
- ensure the live command/turn/recommendation surface remains appropriately available under clock pressure without obscuring board content or keyboard focus
- use device-specific composition where necessary rather than simply wrapping desktop chrome

Do not assume one identical sticky strategy is correct for desktop, tablet, and phone. Use the measured baseline to choose the least intrusive composition.

### 3. Add progressive disclosure for low-frequency maintenance/destructive controls
Create one clear secondary `Manage` / `Tools` disclosure or equivalent bounded surface for low-frequency actions.

Keep immediately discoverable during draft use:
- board-view switch
- search
- position filtering
- My Draft
- Taken/Mine mode
- current draft/session identity as needed to avoid ambiguity
- data freshness / ESPN attention state

Move behind the secondary disclosure unless runtime evidence strongly justifies otherwise:
- New Draft
- Delete Draft
- Autosave control
- Mock Audit
- Update Rankings
- Customize Board
- Restore FantasyPros order
- Reset all
- other clearly maintenance/debug/setup actions of similar frequency

Requirements:
- no functionality removed
- destructive controls retain existing guarded/armed semantics
- disclosure is keyboard-accessible and has clear information scent
- closing the disclosure returns focus predictably
- the default draft surface should not visually compete with these secondary actions

### 4. Collapse Draft Setup after initialization / meaningful progress
Teams / Pick Slot / Rounds must remain easy to configure before drafting.

After valid setup and meaningful draft progress begins, replace permanently expanded setup inputs with a concise readable summary such as `10 teams · Pick 10 · 16 rounds` plus an explicit `Edit` action.

Requirements:
- editing remains available
- no draft-state/persistence semantics change
- do not silently mutate settings by collapsing/expanding
- if existing logic permits settings changes mid-draft, preserve the current behavior and warnings/guards rather than inventing new semantics
- restored/saved sessions render an accurate summary

### 5. Harden frequent interaction targets
Address the compact-target findings without destroying information density.

Minimum requirement:
- pointer targets must satisfy WCAG 2.2 Target Size (Minimum) or a valid spacing/equivalent exception
- explicitly review the previously identified 20–22px target-star affordance, 26px pressure actions, 27–29px setup controls, and compact toolbar/status/tier controls
- at touch-oriented breakpoints, increase effective hit areas for high-frequency actions where practical without bloating player-card density

Do not convert the entire dense board into oversized mobile-style controls on desktop.

### 6. Harden the 769–900px band
This band received independent concern because status wrapping and command-grid changes overlap structurally.

Required outcome:
- no vertical overlap/occlusion between persistent surfaces
- no hidden focused controls
- no document horizontal overflow
- high-frequency draft controls remain understandable without maintenance actions taking over multiple persistent rows
- command Waiting/Near/On-the-Clock states remain visually distinct and stable
