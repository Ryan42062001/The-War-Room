# WR-008 — Project Maturity / Maintenance Mode Rule

TASK ID: WR-008
ROLE: Manager / Architect
STATUS: COMPLETE

OBJECTIVE:
Persist a project-maturity rule that allows Roadmap Discovery to conclude that no successor production milestone is currently justified and permits the Manager to place the War Room into **MAINTENANCE / STABLE** mode rather than creating features merely to sustain development activity.

VERIFIED STARTING STATE:
- Canonical `main` before WR-008 edits: `2899b10ae6d621e41bf7db4f5cdc443bb09774bd`
- WR-007 Roadmap Discovery is active and assigned to R&D
- WR-007 currently assumes a strongest successor milestone and runner-up must be recommended
- canonical workflow already says not to invent speculative work merely for utilization, but it does not yet define a formal maintenance/stable outcome or reactivation triggers
- no production implementation is authorized during WR-007

REQUIRED WORKFLOW BEHAVIOR:
- Roadmap Discovery may conclude that no sufficiently valuable successor milestone is justified
- no feature or milestone should be created merely to maintain development activity
- when evidence does not support a sufficiently valuable successor, R&D may recommend MAINTENANCE / STABLE mode
- Manager retains final authority to accept or reject the maintenance recommendation
- maintenance mode means no active production milestone is assigned by default
- active development resumes only when a legitimate trigger exists, including:
  - verified defects
  - real-world user feedback
  - changed external dependencies
  - new product requirements
  - materially valuable opportunities
  - seasonal/data updates
  - previously unresolved risks becoming actionable
- Roadmap Discovery evidence should explain why leading candidates do or do not clear the threshold for active development
- WR-007 must allow either a justified successor-milestone recommendation or a justified maintenance/stable recommendation

NON-GOALS:
- no production-code changes
- no automatic transition to maintenance before WR-007 evidence is reviewed
- no new production milestone
- no specialist assignment created merely to record this rule
- no change to existing product architecture or durable product decisions

ACCEPTANCE CRITERIA:
- canonical workflow defines MAINTENANCE / STABLE mode and reactivation triggers
- WR-007 explicitly permits a no-successor recommendation
- roadmap and project state explain that Roadmap Discovery may end in either a selected milestone or maintenance/stable mode
- R&D handoff reflects the revised discovery outcome options
- Manager handoff records the rule adoption
- production implementation remains unauthorized

RESULT:
Workflow/documentation change only. Production behavior unchanged.
