## Required experiment design

### 1. Scope
- QB, RB, WR, TE only.
- No K/DST modeling in this experiment.
- No production files may consume experiment output.
- Experiment code/artifacts must remain isolated under `.ai/research/` or another explicitly non-production research-only location approved by the existing task boundaries.

### 2. Rights-conservative source set
Build a source/license manifest before training anything.

Permitted starting families only where current documentation clearly supports the intended research use, for example:
- nflverse play-by-play / computed player and team stats with documented open licensing;
- ffverse `ffopportunity` outputs/models where licensing is documented and attribution requirements are met;
- nflverse FTN charting subset where CC-BY-SA attribution/terms are satisfied;
- additional sources only after R&D documents their exact license/terms and why the experiment may use them.

Explicitly prohibited unless separate rights are established:
- PFF data, grades, Derived Data, screenshots, manual transcription, exports, or API data;
- NFL Next Gen Stats / NFL Pro data as a systematically retrieved experiment input;
- FantasyPros API/historical data for training or benchmarking unless rights for that exact use are established;
- any paid/private source whose terms are unclear.

Do not infer that technical accessibility equals permission.

### 3. Point-in-time corpus
Construct a leakage-safe historical corpus.

For each target season Y:
- features must contain only information available before a documented preseason/draft cutoff for Y;
- no Week 1+ data from target season Y may enter features;
- do not use season-final roster/depth/injury state as if it were known preseason;
- record the cutoff rule and source timestamp logic;
- prefer at least four rolling target seasons if source consistency permits; if fewer are defensible, explain why and reduce confidence accordingly.

### 4. Targets
Primary statistical targets:
- Full-PPR points per active game;
- games active / availability when a defensible point-in-time target/feature design exists;
- season Full-PPR points or distribution derived from the above.

Keep league-specific replacement-adjusted value downstream of player-performance forecasting.

If current open availability data is insufficient, run performance-only experiments and report availability as an explicit missing stage rather than fabricating a model.

### 5. Model families
At minimum compare:
- a transparent naive/statistical baseline;
- a transparent regularized position-specific model;
- one higher-capacity challenger such as gradient boosting if the data volume supports it.

Do not assume the more complex model wins.

Position-specific models are preferred unless evidence supports another design.

### 6. Feature discipline
Candidate features may include only rights-cleared, point-in-time information such as:
- prior-season / multi-season recency-weighted PPR production;
- attempts/carries/targets/receptions and opportunity shares;
- air-yard/target-share style metrics derived from permitted PBP;
- expected-fantasy-opportunity features where licensed;
- team play volume / scoring / EPA context from permitted data;
- age / experience / draft capital where source rights are clear;
- team-change and depth-role features only where point-in-time source history is defensible.

No target-season hindsight features.

### 7. Evaluation
Report by position and pooled where appropriate:
- MAE and/or RMSE for Full-PPR points per active game;
- Spearman rank correlation / rank error;
- top-N hit/miss behavior relevant to fantasy drafts;
- season-total error where availability is modeled;
- replacement-adjusted value error if computed;
- calibration / interval coverage if uncertainty bands are produced;
- simple-baseline vs regularized vs challenger deltas;
- bootstrap/paired uncertainty where practical.

Do not manufacture a direct ECR superiority claim without lawful contemporaneous ECR data.

### 8. 2026 frozen shadow snapshot
If technically feasible before target-season outcomes contaminate the process, create and commit a compact 2026 preseason shadow prediction snapshot for QB/RB/WR/TE using only data available at the documented freeze time.

The snapshot must:
- record timestamp/cutoff/source versions;
- remain research-only and disconnected from production;
- include enough fields to evaluate predictions prospectively later;
- avoid restricted source data;
- clearly identify missing availability/rookie-context inputs.

If a clean freeze is no longer possible, state that explicitly and do not reconstruct one retrospectively.
