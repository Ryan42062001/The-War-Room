# WR-004 — Parallel Task Orchestration Workflow Upgrade

TASK ID: WR-004

OBJECTIVE:
Upgrade the canonical War Room operating procedure so the Manager explicitly evaluates safe parallelism, classifies task dependencies, creates Parallel Work Waves when multiple independent assignments exist, and always provides an activation plan showing which employee chats can work now.

WHY IT IS NEEDED:
The existing workflow correctly defines roles, task IDs, evidence, validation, audit, merge gates, and canonical state, but it does not explicitly require the Manager to optimize for safe parallel throughput. Without an explicit rule, independent work can be serialized unnecessarily.

VERIFIED STARTING STATE:
- Repository: `Ryan42062001/The-War-Room`
- Canonical `main` before WR-004 edits: `241fe2b4d9c4c9e81709a723f6f20e0d5b4e9a55`
- `.ai/shared/WORKFLOW.md` is the canonical workflow
- WR-002 is the sole unfinished milestone task and is blocked awaiting user-supplied Level-4 live evidence
- Builder has no active assignment
- Research has no active assignment
- Auditor owns WR-002 evidence evaluation

REQUIRED BEHAVIOR:
- Manager explicitly evaluates parallelism whenever determining next work
- candidate dependencies are classified as INDEPENDENT, SOFT DEPENDENCY, or HARD DEPENDENCY
- independent tasks are preferred for parallel execution when safe
- two or more independently executable assignments are grouped into `PW-###` Parallel Work Waves
- every wave records task ID, role, objective, dependency status, branch/work area, expected output, and integration considerations
- every Manager response ends with an ACTIVATE NOW plan covering Manager, Builder, Research, and Auditor
- every active specialist receives an exact short activation message
- IDLE remains valid when no useful independent work exists
- parallel PRs use separate branches, minimize overlap, track starting SHAs, re-check target advancement, and rerun affected validation after meaningful integration changes
- workers do not independently reconcile `.ai/shared/*`; the Manager remains the normal canonical-state authority
- optimize for useful throughput, not worker utilization

NON-GOALS:
- no production-code changes
- no creation of speculative tasks merely to demonstrate parallelism
- no change to WR-002 acceptance criteria
- no reassignment of Builder or Research without a real approved task
- no milestone scope expansion

TEST REQUIREMENTS:

- verify workflow preserves existing Task ID, evidence, validation, audit, merge, stale-branch, and handoff rules
- verify new parallelism rules are internally consistent with Manager-only canonical-state ownership

ACCEPTANCE CRITERIA:
- canonical `.ai/shared/WORKFLOW.md` includes dependency classification, parallel wave, activation-plan, PR-safety, and workload-priority rules
- Manager handoff records adoption of the upgrade
- current task routing remains truthful: WR-002 Auditor work remains the only useful specialist assignment; Builder and Research remain idle
- no production files changed

EXPECTED HANDOFF:
Manager handoff with the verified starting SHA, workflow files updated, parallelism decision for the current backlog, active/idle role state, and current canonical checkpoint.
