A later green docs Governance run must not be used to bypass A. This is a process deadlock, not a request to relax product CI.

**Impact:** Indefinite `MERGED / NOT CLOSED` and pinned-canary blockade, or pressure to relabel a failing original canary, silently substitute a newer green run, fabricate retroactive authorization or leave a defective integration on main.

If the original run fails/is absent, cancelled, irrevocably stalled, wrong-SHA or otherwise unprovable, preserve that immutable original result as FAILED/UNVERIFIED and forbid AS-IS closure, but permit a **separate prospective Manager correction/rollback disposition** to authorize a narrowly scoped new corrective/revert task, independent audit when required, and a genuine required CI on that task's OWN landed merge SHA. Require bounded overlap/custody reconciliation, original failure retained, independent Manager review and canonical Governance after any eventual corrected-state closure. Define a specific escalation for stranded queued/running canaries (with original SHA/status pinned) rather than treating a later main Governance success as fulfillment.

**Validation:** Trace (a) original A FULL SUCCESS + exact custody => eligible separate AS-IS decision, (b) A genuine FULL FAILURE => original remains FAILURE, distinct corrective/rollback authorization permitted, B independently audited and exact-B FULL SUCCESS before corrected-state closure, (c) missing/cancelled/stalled/wrong-SHA A => no AS-IS and no implicit green substitution, explicit blocked/remediation path.
