## Problem / blocker
Repository-wide browser CI is intermittently failing on unchanged product surfaces while research/audit-only PRs are being validated. This reduces the trustworthiness and efficiency of the canonical merge gate.

Observed evidence includes:
- WR-039 CI run `34613965662`, attempt 1: command-bar slot locator detached/hidden during `locator.fill` after phone + 164/164 unit tests passed;
- same WR-039 unchanged-head retry: 164/164 unit tests passed, then production-browser persistence state existed where the harness expected `null`;
- WR-040 audit branch push run `34621397234`: `npm test` failure despite branch diff being only `.ai/auditor/**`;
- WR-040 PR #130 run `34621843706`, attempt 1: `npm test` failure on unchanged Auditor-only head;
- the single unchanged-head retry of that PR later passed the full suite, confirming nondeterministic/state-isolation behavior rather than a deterministic Auditor-document defect.

The Work Helper exists specifically for this cross-layer persistent repository/CI problem.

## Required diagnosis
Independently reproduce and isolate the observed failure classes where feasible:
1. command-bar control detaches/becomes hidden during fill;
2. browser persistence/state unexpectedly survives where a clean/null state is expected;
3. any shared browser lifecycle, storage, parallelism, asynchronous render, fixture cleanup, or test ordering mechanism connecting the failures.

Determine whether the failures are:
- one common state/lifecycle defect;
- multiple independent nondeterministic tests;
- CI-specific timing/environment behavior;
- test isolation defects;
- or another evidence-backed cause.

Do not force a common explanation if evidence shows distinct causes.

## Remediation rules
A valid fix must improve determinism without weakening validation.

Do NOT:
- delete or skip meaningful assertions merely to get green CI;
- blanket-retry flaky tests as the primary fix;
- inflate timeouts without evidence that timeout duration is the root cause;
- hide failures with `continue-on-error`;
- reduce test coverage;
- change production behavior just to satisfy a brittle test;
- conflate the CI repair with WR-042 source-custody work.

Prefer deterministic setup/cleanup, stable locator interaction, state reset, explicit browser lifecycle, reliable readiness conditions, and isolated test fixtures.
