## Blocking findings

### WR-076-AUD-01 — operand-role ambiguity

The 1.1.0 lock defines generic transforms as `improve=(B-C)/B` and `regress=(C-B)/B` with B as baseline and C as candidate, while derived expressions use calls such as `improve(candidate,primary)` and `regress(candidate,primary)` without a normative function signature binding argument names/order. A positional interpretation can reverse sign and pass/fail.

Required remediation:

- define one explicit machine-readable signature with named arguments, e.g. `improve(candidate,baseline)=(baseline-candidate)/baseline` and `regress(candidate,baseline)=(candidate-baseline)/baseline`;
- bind every derived/position/season/ordering/secondary-baseline call to that signature;
- bind denominator and zero/negative-denominator handling to the named baseline operand;
- eliminate B/C or positional ambiguity completely.

### WR-076-AUD-02 — synthetic conformance fixture missing

The 1.1.0 lock publishes expected bootstrap digest/endpoints/gate but does not freeze the exact privacy-safe synthetic input fixture needed to regenerate those outputs independently.

Required remediation:

- freeze the complete synthetic input fixture or equivalent deterministic reference code before any model result work;
- bind the fixture by identity/version and SHA-256;
- freeze canonical serialization/order/types and exact candidate/baseline/target or error inputs needed to reproduce the 5,000-replicate vector;
- bind input hash, expected replicate digest, Q.025, Q.975, gate result, NumPy version and execution semantics together so an Auditor can reproduce the vector without inference.
