## Required architecture / security properties

The exact implementation is Work Helper-owned within the authorized files, but the resulting invocation path must satisfy all of the following:

1. **Provider operations are read-only by construction.** The secret-bearing provider code may perform only the minimum authentication plus object GET/download operations needed to retrieve the exact allowlisted B2/R2 objects. Do not call or import any custody helper/routine that can PUT, upload, copy, multipart-upload, delete, overwrite, mutate metadata/tags, change retention, change Legal Hold, change Bucket Lock, or otherwise mutate provider state.
2. **Fixed allowlist.** The four keys/digests/sizes above are committed as reviewed configuration/evidence. Runtime inputs may not widen them. Unknown keys fail before any request.
3. **Existing secret set only.** Do not create or require new provider credentials and do not change current credential scope/policy. Provider credentials must be scoped in the workflow only to the trusted read step; do not place them at job/global environment scope.
4. **Trusted-code boundary.** Secret-bearing code must come from the reviewed WR-061/default-branch implementation, not from an arbitrary R&D target commit. Any later WR-059 consumer/parser must execute only after provider secrets have been removed from its environment and must not be able to invoke the secret-bearing retriever.
5. **Exact byte verification.** Recompute SHA-256 and byte size immediately after every provider retrieval. Any mismatch fails closed before consumer parsing. If both B2 and R2 are read, verify equality to the pinned digest/size.
6. **Ephemeral raw bytes.** Store provider bytes only under runner-temporary storage, delete them on success/failure, never commit them, and never publish them as Actions artifacts or logs.
7. **No upstream byte refresh.** Do not fetch source bytes from GitHub, nflverse, or another upstream provider. This path is retained-object read only.
8. **No secret leakage.** Mask current secrets and emit only privacy-safe provider/key/digest/size/status evidence. Do not log authorization headers, signed URLs, tokens, IDs that are designated secret, or raw content.
9. **Consumer boundary for WR-059.** Provide a reviewed mechanism by which a fixed WR-059 no-scoring consumer can process the verified ephemeral bytes after credentials are removed. Derived non-raw evidence may be returned through a privacy-safe mechanism; raw bytes may not leave runner temp. Do not implement R&D evidence semantics inside Work Helper merely to bypass role separation.
10. **Fail closed on architecture uncertainty.** If the safe consumer boundary cannot be established without broader workflow/runtime/credential changes than this task authorizes, stop and return the precise blocker to Manager.
