# WR-012 — Layout Efficiency & Information Architecture R&D

TASK ID: WR-012
ROLE: Research & Development (R&D)
STATUS: ASSIGNED
PARALLEL WAVE: PW-001

## Objective
Determine the most efficient evidence-backed layout and information hierarchy for The War Room's live draft workflow, then identify bounded layout/UX improvements that would materially reduce scan time, wasted space, control friction, or cognitive load without changing ranking, scoring, recommendation, draft-state, persistence, or ESPN-sync behavior.

This is research/discovery only. Production implementation is NOT authorized.

## Why it is needed
The user explicitly asked whether the current website layout can be researched and improved. The War Room already has deliberate density work, responsive behavior, Position Tiers, Overall view, a command bar, recommendation/pressure widgets, My Draft, and multiple sticky controls. The next useful step is evidence-backed optimization rather than another subjective redesign pass.

## Required research questions
1. What are the highest-priority decisions a draft-day user must make in the first 1–3 seconds of looking at the screen?
2. Which information should remain persistently visible, which should be contextual, and which should be progressively disclosed?
3. Does the current stack of sticky header/toolbar/status/tier-navigation/command surfaces use too much vertical viewport, especially on laptop/tablet/mobile?
4. Is Position Tiers currently the right default information architecture, and how should Overall remain accessible without duplicating controls?
5. Are search, position filters, board-view switching, marking mode, My Draft, session controls, ranking/customization controls, and destructive actions grouped according to task frequency and risk?
6. Can the recommendation, current-pick status, board pressure, roster needs, and best-available information be combined or reordered to reduce scan distance while preserving trust and explainability?
7. What layout patterns are supported by current authoritative UX/accessibility research for high-density real-time dashboards and touch interfaces?
8. What useful patterns can be learned from current fantasy draft assistants / draft boards without copying proprietary UI or assuming competitor popularity equals usability?
9. Which desktop, tablet, and mobile layouts should materially differ rather than merely wrap the same controls?
10. Which changes would create the biggest efficiency gain with the smallest implementation/regression risk?

## Core draft-day tasks to optimize
Evaluate the layout against at least these tasks:
- know whether it is my turn / how soon my pick is
- identify the best recommended action and reason
- compare best available players across positions
- understand tier/position pressure
- search for a specific player
- mark a player Taken or Mine quickly and correctly
- understand roster construction / remaining needs
- switch Position Tiers / Overall when needed
- confirm ESPN sync/trust state without distracting from the pick decision
- access lower-frequency settings, session, rankings, customization, recovery, and destructive controls without keeping them visually dominant

## Candidate improvement categories
Consider, but do not assume these are correct:
- reducing or collapsing low-priority sticky chrome
- consolidating command/status/recommendation surfaces
- separating primary draft actions from maintenance/settings actions
- moving infrequent controls into a menu/details surface
- adapting command-bar composition by viewport and draft state
- stronger desktop multi-column use vs mobile single-flow use
- keeping recommendation + next-pick status spatially close to the board
- making My Draft/roster needs easier to access without obscuring the board
- improving search/filter grouping
- preserving trust states while reducing status noise

## Non-goals / prohibitions

## Edge cases
Evaluate recommendations against:
- long player/team text
- sync `Needs attention` / `Unavailable` states
- on-the-clock vs waiting/near-pick command states
- My Draft open
- draft settings expanded
- multiple saved sessions / long session names
- custom board/edit mode
- search active
- 20-team / long-round configurations where control labels/counts may grow
- keyboard navigation and screen-reader semantics
- phone safe areas and browser chrome reducing available height
