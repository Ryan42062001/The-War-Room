## Objective

Harden Workflow V3.1.1 into the first bounded V3.2 safety upgrade by closing two related execution-lane identity gaps discovered after WR-052:

1. task-scoped local preflight/finish checks currently report the checked-out branch but do not fail when it differs from the branch assigned in `ACTIVE_TASKS.json`;
2. the static state checker validates task ID and STATUS against the task spec but does not verify core machine-readable task-contract fields such as TARGET BRANCH, EXECUTION MODE, and dependency class.

The upgrade must prevent a worker from receiving a green workflow check while operating from a stale/wrong execution lane.

## Required implementation

- Add deterministic branch-identity enforcement to `workflow-preflight.mjs`.
- Add deterministic branch-identity enforcement to `workflow-finish-check.mjs`.
- Detached HEAD or a branch different from the registry assignment must fail unless a narrowly documented validation-only exception is explicitly authorized by this task.
- Extend static state validation so active task specs cannot silently disagree with registry values for:
  - TASK ID;
  - STATUS;
  - TARGET BRANCH;
  - EXECUTION MODE;
  - dependency class (`INDEPENDENT`, `SOFT`, `HARD`).
- Preserve compatibility with human-readable suffixes such as `DEPENDENCY: HARD — ...`.
- Add focused regression coverage proving matching identities pass and stale branch/spec identities fail.
- Update canonical workflow documentation to describe the new lane-identity gate.
- Keep schema v3 unless a schema change is actually necessary.

## Required regression cases

At minimum prove:

1. assigned branch == checked-out branch => PASS;
2. checked-out branch != assigned branch => FAIL;
3. detached HEAD with an assigned branch => FAIL;
4. task spec TARGET BRANCH mismatch => static state FAIL;
5. task spec EXECUTION MODE mismatch => static state FAIL;
6. task spec dependency-class mismatch => static state FAIL;
7. current WR-042 / WR-043 task specs remain valid under the stronger checker.
