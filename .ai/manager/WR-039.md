## Objective
Design and freeze a new, explicitly versioned, prospective upstream evidence/provenance contract for Returning-Player v2 research before any new model scoring or result inspection.

This task is NOT a repair of WR-033, NOT a replay of the deleted WR-033 Players asset, and MUST NOT claim equivalence to the frozen WR-033 input surface. WR-033 / WR-D005 remain historical v1 research architecture with an unresolved provenance gap for later Phase-5 composition.

The purpose of WR-039 is to prevent a repeat of WR-037 by ensuring future research retains enough immutable evidence to audit every scored row even if an external source later changes or disappears.

## Hard boundaries

- inspect 2026 regular-season outcomes;
- score, fit, tune, compare, rank, or evaluate any new Returning-Player v2 model;
- rerun WR-035 or generate new season-total results;

Allowed work is evidence-contract research and documentation under `.ai/research/**` plus the task-scoped branch/PR needed to publish that contract.

## Required contract contents
The proposed Returning-Player v2 evidence contract must define, before scoring:

### 1. Versioned source inventory
For every upstream input needed by the future v2 expected-performance research path, record at minimum:
- canonical source/provider;
- exact acquisition method and URL/API endpoint where applicable;
- acquisition timestamp;
- target-season/cutoff semantics;
- source/version/release identifier;
- SHA-256 or stronger content digest;
- byte size;
- schema/column contract;
- rights/license/redistribution status;
- mutable-vs-immutable source classification;
- required fallback behavior when the source cannot be retrieved exactly.

### 2. Durable retention strategy
Define a retention method that does not rely on an expiring GitHub Actions artifact or a mutable external URL as the sole source of truth.

When rights permit, preserve the exact source bytes or a content-addressed immutable copy under project-controlled storage.

When rights do not permit preserving raw bytes, the contract must still preserve enough audit-safe derived evidence to prove exact model inputs and outputs later without circular reconstruction. At minimum this must include the complete keyed feature matrix or deterministic keyed feature hashes and the complete keyed prediction surface for every scored row.

The contract must state the retention lifetime and who/what is authoritative.

### 3. Full-row keyed evidence
Define one stable row key, at minimum sufficient to uniquely identify player, position, and target season.

Require persisted machine-readable evidence for EVERY scored row, including rows with zero realized games or otherwise excluded from active-only evaluation summaries.

The evidence package must allow an auditor to verify:
- exact feature identity;
- preprocessing identity;
- exact model specification/version;
- exact prediction identity;
- missing/duplicate-key failure behavior;
- row counts and inclusion/exclusion reasons.

Aggregate MAE/RMSE/correlation equality is never a substitute for keyed identity.

### 4. Model/reproducibility lock surface
Specify all artifacts that must be frozen before future scoring, including as applicable:
- feature schema and transforms;
- preprocessing parameters;
- model family/hyperparameters;
- training/validation/confirmation split logic;
- seeds;
- cutoff rules;
- environment/dependency lock;
- code commit SHA;
- source manifests;
- machine-readable contract hash;
- deterministic command(s) used to rebuild the evidence package.

### 5. Prospective chronology
Define an explicit chronology that separates:
1. evidence/source contract freeze;
2. independent audit of that contract;
3. later model scoring/evaluation under the exact audited contract;
4. later season-total composition research;
5. independent audit before any downstream Phase-6 use.

No result from step 3 or later may be inspected before the contract in step 1 is frozen.

### 6. Reuse vs re-versioning disposition
Determine, with evidence, which prior components can legitimately remain reused as accepted historical components and which must be re-versioned for v2.

At minimum address:
- WR-033 expected-performance layer;
- WR-034 expected-games layer;
- source/provenance governance inherited from WR-029;
- whether the future v2 path can reuse the same Ridge specification without claiming frozen-WR-033 replay identity;
- what new identifiers/names are required so v2 cannot be confused with v1.

Do not make the final model-adoption decision in WR-039; define the admissible evidence contract and versioning boundary only.

### 7. Fail-closed policy
The contract must fail closed if any required source/evidence package is missing, mutable without a locked copy, license-incompatible, internally inconsistent, or not independently auditable.

## Required outputs
Create/update research-only artifacts sufficient to freeze the contract, including:
- a human-readable Returning-Player v2 evidence contract;
- a machine-readable manifest/lock with deterministic hash;
- a source-rights/retention matrix;
- a concise R&D handoff.

Publish one immutable task PR/head for independent audit.
