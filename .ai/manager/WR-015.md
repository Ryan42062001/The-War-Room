## Independent synthesis

### Strong agreement between WR-012 and WR-013
1. **Broad redesign is not justified.** Position Tiers, one-action Overall switching, the command-state model, mobile containment, My Draft separation, and current overflow protections are valuable foundations to preserve.
2. **Persistent chrome / sticky hierarchy is the strongest layout opportunity.** Current independent sticky layers and fixed offsets consume meaningful desktop/tablet vertical budget and are structurally fragile when wrapping changes actual heights.
3. **Low-frequency maintenance/destructive actions compete too much with live-draft controls.** Session maintenance, ranking/customization tools, audit actions, restore/reset, and destructive actions should not receive the same persistent prominence as turn state, recommendation, Taken/Mine, search/filter, and sync attention.
4. **Target ergonomics deserve bounded hardening.** WR-013 verified several frequent sub-30px targets; WCAG 2.2 requires at least 24x24 CSS px or a qualifying exception/spacing arrangement.
5. **The 769–900px band deserves explicit runtime validation.** Existing tests prove horizontal containment, not sticky overlap, focus obscuration, or above-fold decision density.

### R&D-specific recommendation accepted with conditions
WR-012 recommends collapsing Teams/Pick/Rounds setup after initialization or meaningful draft progress. Auditor did not independently identify this as a defect, but repository evidence confirms those controls remain permanently visible in the command surface. Manager accepts this as a bounded progressive-disclosure candidate because it is directly related to persistent decision density and can be implemented without changing draft-state semantics.

### Evidence gaps that must become implementation gates
Before changing production layout, Builder must capture deterministic pre-change geometry on representative viewports. Required evidence includes sticky-union height, first actionable board Y, above-fold player-choice count, overlap/occlusion, keyboard focus visibility, target dimensions, and page/runtime errors. The absence of exact baseline pixels in WR-012/013 is not a reason to abandon the opportunity; it is a pre-change measurement requirement.

## Manager decision
**APPROVE a bounded production milestone: Draft-Day Layout Efficiency.**

The evidence is sufficient to justify targeted implementation because two independent streams converge on the same hierarchy problems and because the proposed fixes are presentation/interaction changes rather than scoring/state/ESPN architecture changes.

The milestone is deliberately narrow:
- coordinate persistent live-draft surfaces and eliminate fragile independent sticky stacking
- progressively disclose low-frequency maintenance/destructive controls behind a clear secondary Manage/Tools surface
- collapse Draft Setup to a concise summary + explicit Edit after valid initialization/meaningful draft progress
- harden frequent interaction targets where the current implementation is below reasonable touch/accessibility thresholds
- directly test the 769–900px stress band and representative mobile/desktop viewports
