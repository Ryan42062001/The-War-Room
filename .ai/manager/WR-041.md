## Objective
Replace the temporary Troubleshooting & Root Cause Engineer concept with a permanent first-class **Work Helper / Super Troubleshooter / Cross-Functional Operator** role while preserving Manager governance, specialist ownership, independent audit, frozen research boundaries, and production merge controls.

## Required architecture
Create and canonically document:
- `.ai/roles/WORK_HELPER.md`;
- `.ai/work_helper/HANDOFF.md`;
- `.ai/work_helper/TROUBLESHOOTING_LOG.md`;
- compatibility redirect/supersession for `.ai/roles/TROUBLESHOOTING.md`;
- workflow/routing updates required for all roles to understand Work Helper escalation.

## Privilege model
Work Helper receives broad repository inspection authority and may freely write `.ai/work_helper/**` plus diagnostic/test branches. Any write outside `.ai/work_helper/**` requires an explicit Manager-approved Work Helper task authorizing the path/category.

The role may perform diagnosis and, when expressly authorized, cross-layer remediation spanning production code, tests, CI/workflows, research tooling, integrations, and recovery paths.

Elevated access does not transfer Manager, Strategy, R&D, Builder, or Auditor decision authority.

## No fixed attempt limit
The normal approximately-three-materially-distinct-attempt anti-loop threshold remains in force for normal roles.

Work Helper is exempt from any fixed numerical attempt ceiling. It may continue evidence-driven diagnosis/remediation while each attempt materially advances understanding, avoids mindless repetition, respects task/write scope, records durable findings, and preserves approval gates for destructive or irreversible actions.

If many approaches fail, Work Helper must widen the investigation and record what has been ruled out rather than stopping because a numerical threshold was reached.

## Governance boundaries
Work Helper may not independently:
- change roadmap or canonical product/model decisions;
- change production ranking authority;
- rewrite Manager-owned `.ai/shared/**` state without explicit Manager authorization;
- bypass frozen research/provenance rules;
- weaken prospective evidence standards;
- approve its own production implementation;
- issue an independent Auditor PASS on work it materially changed;
- merge production/milestone work unless explicitly delegated by Manager under the canonical merge gate.

Manager retains task/roadmap/integration/merge authority. Auditor remains independent verification authority. Draft Strategy retains recommendation-policy authority. R&D retains research/model/source evidence ownership. Builder retains normal production implementation ownership.

## Activation contract
Every Work Helper assignment must state:
- TASK;
- MODE: `DIAGNOSIS ONLY`, `DIAGNOSIS + REMEDIATION`, `CROSS-ROLE RECOVERY`, `WORKFLOW / CI TROUBLESHOOTING`, or another bounded mode;
- PROBLEM / BLOCKER;
- TARGET repo/branch/PR/SHA when applicable;
- AUTHORIZED READ SCOPE;
- AUTHORIZED WRITE SCOPE;
- EXECUTION MODE;
- REQUIRED EVIDENCE;
- GOVERNANCE BOUNDARIES;
- EXPECTED HANDOFF.

## Scope boundaries
This task is control-plane only. Do not change production behavior, draft strategy, football-model policy, WR-039 evidence-contract substance, WR-040 audit scope, or WR-D001 production ranking authority.

## Acceptance criteria
- Work Helper is a permanent first-class role in `.ai/shared/WORKFLOW.md`.
- Work Helper role charter and persistent workspace exist.
- old temporary troubleshooting role is unambiguously superseded;
- normal roles know when to escalate/recommend Work Helper;
- Work Helper has no fixed attempt ceiling but must remain evidence-driven and scoped;
- explicit write/governance boundaries prevent superuser access from becoming second-Manager authority;
- Manager activation output includes Work Helper status;
- current canonical state reports Work Helper `IDLE` absent a real assignment;
- WR-039 remains operationally untouched;

- exact-head CI succeeds before merge.
