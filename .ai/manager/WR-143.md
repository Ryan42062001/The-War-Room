## Why this task exists

WR-137 independently returned PASS WITH NON-BLOCKING FINDINGS on the closed WR-136 terminal-turn repair and retained one LOW finding, WR137-F01. The finding remains intentionally unresolved after WR-D055 and WR-D066.

Current canonical `js/war-room-command-bar.js` computes command mode as:
- no state -> waiting;
- `state.myNextPick === null` -> complete;
- otherwise on-clock or waiting.

Current canonical draft-state correctly permits `myNextPick:null` before authoritative draft completion when the user's final owned pick has already been consumed but another team still owns the final overall pick. In the actual 2-team × 5-round slot-1 sequence, after 9/10 numbered picks, the user's last own pick (9) is consumed, `myNextPick:null`, but overall pick 10 remains. The current command bar can therefore render **DRAFT COMPLETE** one pick early.

The existing WR-136 real-browser regression explicitly records slot1 9/10 with `expectedMode:null`, so it does not assert the command-bar UI at the exact inherited gap. This task closes only that UX/coverage defect.
