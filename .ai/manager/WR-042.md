## Required work
### 1. Freeze acquisition scope before inspecting source content for research claims
Define the exact historical seasons/assets and target-season cutoff semantics needed for the future v2 development path from the accepted contract and prior prospective chronology. Selection must be based on the predeclared research design, not model performance.

### 2. Acquire and identify every exact source instance
For each exact asset, record at minimum:
- `source_instance_id = src-sha256-<digest>`;
- source class, provider, repository;
- exact acquisition method and canonical endpoint;
- UTC acquisition timestamp;
- release/tag/version, release ID, asset ID/name, provider update time where supplied;
- SHA-256 of exact downloaded bytes and byte size;
- media/compression type;
- ordered raw schema plus schema SHA-256;
- row count and exact approved-column list;
- cutoff/availability semantics and mutability classification;
- acquisition code SHA and exact command;
- `ADMITTED`, `REJECTED`, or `UNAVAILABLE` status with reason.

### 3. Perform per-instance rights/retention disposition
For every source instance preserve:
- license identifier and authoritative license/reference URL;
- attribution text;
- upstream caveats;
- raw-custody / minimal-extract / restricted disposition;
- whether public redistribution is prohibited or undecided;
- reason the instance is lawful/auditable for project research custody.

License uncertainty fails closed. An open-source loader is not proof of rights to underlying data.

### 4. Establish durable custody before parsing/use
Where rights permit, preserve exact downloaded bytes in project-controlled content-addressed immutable custody before parsing.

Required custody evidence:
- retained-object URI/path containing or binding the SHA-256;
- retained-object digest equality to the acquired bytes;
- append-only/object-lock/version-retention semantics or equivalent overwrite protection;
- provider attribution/license mapping;
- second independently retrievable project-controlled copy;
- immediate existence/digest verification report;
- documented future quarterly verification method.

Where raw retention is not permitted, build only the rights-compatible derived evidence allowed by the contract, and prove an independent auditor can lawfully access/verify the reference. Hashes without an independent reference do not satisfy custody.

### 5. Freeze the source-snapshot manifest
Create one machine-readable manifest containing every exact source instance, rights disposition, retained-object/derived-evidence identity, cutoff, schema, and digest. Give the complete manifest a stable `source_snapshot_id`, canonical serialization, and SHA-256.

### 6. Freeze no-outcome cohort/source eligibility evidence
Create the pre-model cohort/source-eligibility manifest needed to prove complete source coverage without joining target outcomes. Use the contract's stable key semantics where applicable and record deterministic inclusion/exclusion/source-availability reasons. Duplicate keys, ambiguous identities, missing source lineage, or unexplained omissions fail closed.

Do not calculate target-season outcome labels or performance metrics.

### 7. Verify frozen sentinels and boundaries
Reconfirm WR-021/WR-023 sentinels, no 2026-outcome inspection, no scoring artifacts, and no production/Phase-6 changes.
