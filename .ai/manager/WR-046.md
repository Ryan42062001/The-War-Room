## Objective
Establish or prove a concrete, reproducible, rights-compatible capability that a later R&D custody task can use to:
1. download exact provider release bytes rather than mutable substitutes;
2. compute and verify exact byte SHA-256 and byte size;
3. place the exact bytes into project-controlled access-controlled content-addressed primary custody when rights permit;
4. place a byte-identical second copy into an independently retrievable project-controlled backup;
5. retrieve both copies later and verify digest equality;
6. preserve attribution/license/custody metadata and overwrite/version-retention semantics;
7. do all of the above without using an expiring CI artifact, mutable URL, or public raw-data mirror as sole authority.

WR-046 does NOT itself admit Returning-Player v2 source instances and must not replace R&D source-custody authority.

## Manager-approved free custody architecture — 2026-09-11
The Manager explicitly authorizes this backend for WR-046 capability proof without changing WR-D008 or the audited WR-039 evidence contract:

- **Primary custody:** private Backblaze B2 bucket with Object Lock enabled, using content-addressed object keys containing SHA-256.
- **Independent backup custody:** private Cloudflare R2 bucket using Bucket Locks, with the same content-addressed object keys.
- **Retention:** lock retained objects indefinitely at the storage layer for the capability proof; later R&D may bind a more specific retention record only if it remains at least as strong as the audited contract requirement (life of dependent model/result plus at least seven years after retirement).
- **Authentication:** least-privilege bucket-scoped credentials stored only as GitHub Actions secrets or equivalent protected secret storage; never commit credentials to Git.
- **Independence:** B2 and R2 are separate providers and each copy must be directly retrievable and independently digest-verified.
- **Authority:** neither GitHub Actions artifacts nor mutable upstream URLs become durable custody authority.

This architecture was selected because the currently observed WR-042 source set is only on the order of megabytes, while both providers currently expose free storage tiers large enough for the present workload. Free-tier economics are not a semantic dependency: if provider pricing later changes, custody validity depends on retained immutable evidence, not continued zero-dollar pricing.

### User provisioning boundary
Work Helper cannot create external Backblaze/Cloudflare accounts or safely manufacture secrets. The user must provision:

1. one private Backblaze B2 bucket dedicated to The War Room with Object Lock enabled;
2. one private Cloudflare R2 bucket dedicated to The War Room with an indefinite Bucket Lock rule covering the custody prefix or full bucket;
3. a bucket-scoped Backblaze application key with only the permissions needed for upload, retrieval, listing/metadata, and retention verification;
4. a bucket-scoped Cloudflare R2 API token/S3 credential with Object Read & Write access only to the selected bucket;
5. protected GitHub Actions secrets for those credentials plus non-secret bucket/account/endpoint metadata as appropriate.

Do not use master/root account credentials when scoped credentials are available.

After the above exists, WR-046 is authorized to resume on its existing branch/PR, replace the earlier AWS proposal with the approved B2+R2 architecture, and complete the full fixture custody/retrieval/lock proof before WR-047 audit.
